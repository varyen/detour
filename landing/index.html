Обход блокировок живёт
на роутере, а не на каждом устройстве

Detour — веб-панель, которая объединяет два независимых движка обхода: прозрачный прокси sing-box (VLESS, Trojan, VMess, WireGuard, Shadowsocks, Hysteria2, TUIC, AnyTLS, SOCKS/HTTP) и DPI-обход zapret, работающий вообще без внешнего сервера. Настраивается мышкой, работает сразу для всей домашней сети — включая телевизоры, консоли и колонки, куда никакой клиент не поставишь.

Установить за три шага Исходники на GitHub

Ничего не уходит в облако: панель, конфиги, ключи и профили лежат только на вашем роутере.

Зачем это нужно

Один раз на роутере — вместо клиента на каждом устройстве

VPN-клиент на ноутбуке решает задачу только для ноутбука. Detour переносит обход на уровень домашней сети: трафик разводится прозрачно, устройствам не нужно ничего знать и ставить.

Телевизор, консоль, колонка, рабочий ноутбук гостя — трафик заворачивается на роутере, клиент не нужен нигде.

Как это работает

DNS подсказывает, файрвол разводит трафик

Когда устройство резолвит домен из списка, dnsmasq кладёт полученный адрес в соответствующий набор (ipset). Дальше правила nat PREROUTING решают, куда отправить соединение — не разбирая содержимое пакетов, поэтому накладные расходы минимальны.

клиент в сети→ dnsmasq + наборы адресов→ nat PREROUTING
адрес в наборе zapret→ на порт 1081→ DPI-обход, соединение остаётся прямым
адрес попал под маршрут по сайту→ свой порт этой цели→ назначенный профиль или цепочка
подошло правило основного туннеля→ на порт 12345→ активный VPN → (WARP) → сайт
торрент с профиля, где он не разрешён→ отбой на подлёте
всё остальное→ напрямую, без потери скорости

UDP при необходимости заворачивается отдельно, через TPROXY — это нужно играм, голосовым чатам и QUIC. Обещание «размеченный адрес скорее не работает, чем идёт мимо VPN» держится и в поломанных состояниях: перезапуск сервиса не открывает трафику прямой путь, а маршрут на исчезнувший профиль отклоняет соединение вместо тихой утечки.

Возможности

Что умеет панель

Ниже — разделы интерфейса и задачи, которые каждый из них закрывает. Все кадры сняты с живого роутера; данные на них обезличены.

Профили и подписки

Профиль добавляется вставкой ссылки vless://, trojan://, vmess://, ss://, socks5:// либо руками по полям; для WireGuard — своя вкладка. Подписка провайдера обновляется по расписанию и сама раскладывает серверы по группе.

  • Сортировка по скорости, пингу и состоянию — видно, через что реально быстро, а не только что первое по алфавиту.
  • Фильтры по группе и стране — сотня профилей перестаёт быть кашей.
  • Массовые операции — выделить, перенести в папку, удалить, выгрузить в файл.
  • Подписка тянется через активный VPN, и только если не вышло — напрямую: адрес панели провайдера часто блокируют как раз там, где вы находитесь.

Проверка, скорость и автопереключение

Пинг говорит только о том, что жив входной узел. Панель проверяет профили по-настоящему: поднимает временный sing-box и ходит через него на реальные адреса, замеряя и скорость загрузки. Мёртвый сервер виден до того, как о нём узнает человек.

  • Автопереключение на живой профиль, когда активный перестал отвечать, — с уведомлением о том, что и почему сменилось.
  • Участие в проверках настраивается на профиле: какие можно включать автоматически, а какие трогать нельзя.
  • Торренты — по разрешению. По умолчанию запрещены везде: большинство провайдеров VPN закрывают аккаунт после первой жалобы, поэтому разрешение выдаётся вручную и только там, где оно допустимо.
  • Свои цели проверки и блок-лист выходных адресов, если нужен конкретный IP на выходе.

Маршруты по сайтам

Разные сайты — через разные выходы одновременно. Маршрут описывает, какой профиль (или целая цепочка) забирает указанные домены, *.поддомены, адреса и подсети.

  • Строгий режим — «только этим путём»: если назначенное подключение не работает, трафик не пойдёт ни в основной VPN, ни напрямую, а просто оборвётся.
  • Через активную цепочку — путь «текущий VPN → маршрутный VPN» вместо прямого выхода.
  • Перехват трафика к прокси — если устройство жёстко прибито к чужому SOCKS/HTTP-прокси, роутер прозрачно применит к нему правила панели.
  • UDP через VPN — отдельным списком или целиком, для игр и голоса.

Режимы туннеля и списки

Два режима на выбор: «только выбранные сайты» (в туннель уходит список) и «всё, кроме исключений» (в туннель уходит всё, что не попало в белый список). Списки принимают домены, *.поддомены, адреса и подсети — с комментариями.

  • Российские адреса — напрямую: список подсетей обновляется сам (MaxMind GeoLite2 или данные RIR).
  • Исключения из исключений — адрес, который числится российским, но должен идти через VPN.
  • Один процесс или по процессу на профиль — на выбор: экономить память роутера или разнести нагрузку.
  • Ссылку можно вставить целиком — панель сама достанет из неё хост.

Цепочки и Cloudflare WARP

Профили выстраиваются в цепочку: клиент → VPN 1 → VPN 2 → интернет. Отдельный сценарий — бесплатный WARP последним хопом: выходной адрес перестаёт выглядеть адресом дата-центра, и сервисы, которые отказывают хостингам, снова начинают работать.

  • Регистрация WARP прямо из панели — через выбранный VPN, потому что на прямые запросы из России API Cloudflare не отвечает.
  • Именованные цепочки включаются одним нажатием с «Обзора».
  • Цепочка как цель маршрута — например, увести в «VPN → WARP» только один домен.

Пустить в дом: публикация сервисов наружу

Обратная задача — не выйти из дома, а зайти в него. Панель выпускает сертификат Let's Encrypt для вашего домена и публикует нужный сервис наружу.

  • По имени — hass.h.example.com на обычном 443-м: не нужно ни выбирать порт, ни надеяться, что чужой Wi-Fi в кафе его пропустит. Все имена делят один уже открытый порт.
  • По порту — HTTPS-реверс-прокси на том же сертификате, с WebSocket и опциональной Basic-авторизацией.
  • Проброс порта — для всего, что не HTTP.
  • Проверка снаружи — доходит ли порт до роутера из интернета; ответ сверяется со счётчиком своего же правила файрвола, поэтому видно и подмену провайдером.
  • Сертификат — HTTP-01 или DNS-01 через API DNS-провайдера; второй способ даёт wildcard и не требует открытого 80-го порта.

Главная под себя и поиск по всему

«Обзор» собирается из карточек: набор, порядок и ширина — перетаскиванием, прямо на месте. График трафика показывает направления или скорость приёма и передачи за час, сутки, неделю или месяц.

  • Палитра команд по Ctrl+K: переключить VPN, открыть раздел, запустить проверку — не отрывая рук от клавиатуры.
  • Светлая и тёмная темы, PWA — панель ставится на телефон как приложение.
  • Каналы в интернет — если провайдеров два, видно оба и то, какой сейчас несёт трафик.

Диагностика и обновления

Всё, за чем обычно лезут по SSH, лежит в «Журнале»: логи sing-box и zapret, журналы проверки и установки, итоговый config.json целиком, действующие правила файрвола и живые соединения.

  • Логи и конфиг — видно ровно то, что панель сгенерировала и запустила.
  • Файрвол — дампы nat, nft и conntrack: куда на самом деле уходит трафик.
  • Самообновление — проверка GitHub Releases раз в шесть часов, установка одной кнопкой, откат к предыдущей версии.
  • Ускорение и SWAP — аппаратное ускорение под присмотром (панель умеет чинить его сама), файл подкачки на флешке создаётся из интерфейса.
С телефона

Та же панель, а не урезанная версия

Панель — PWA: ставится на домашний экран и открывается как приложение. С телефона доступно всё то же самое, включая списки, маршруты и диагностику. А когда активный VPN отваливается, роутер присылает Web Push — по каналу в обход упавшего туннеля, иначе уведомление не дошло бы именно тогда, когда оно нужно.

Тема

Тёмная по умолчанию, светлая — одним нажатием

Тема переключается в шапке и запоминается на устройстве. Всё остальное остаётся на месте: те же карточки, те же цифры.

Платформы

Две прошивки, один интерфейс

Основная платформа — OpenWrt / GL.iNet. Вторая — Keenetic с Entware: там нет nftables и NFQUEUE, поэтому часть механик сделана иначе, а движок zapret2 недоступен физически.

Референсное устройство — GL.iNet GL-BE9300 (Flint 3) на OpenWrt 23.05, aarch64, musl; проверялось также на GL-MT6000 (Flint 2). Keenetic-ветка собирается из того же исходника, но часть её возможностей на живом устройстве ещё не проверена — это честно отмечено в CHANGELOG.

Установка

Один пакет, дальше всё само

Панель — slim-пакет .ipk без бинарников. После установки она сама прописывает opkg-фид проекта и подтягивает sing-box и tpws-zapret в фоне.

1

Скачать пакет своей платформы

Из GitHub Releases: detour_X.Y.Z_all.ipk для OpenWrt / GL.iNet либо detour-keenetic_X.Y.Z_all.ipk для Keenetic / Entware. Рядом лежит .ipk.sig — подпись релиза.

2

Скопировать на роутер и установить

# OpenWrt / GL.iNet
scp detour_X.Y.Z_all.ipk root@192.168.8.1:/tmp/
ssh root@192.168.8.1 'opkg install /tmp/detour_X.Y.Z_all.ipk'

# Keenetic / Entware (Entware смонтирован в /opt)
opkg install /tmp/detour-keenetic_X.Y.Z_all.ipk
3

Подождать полминуты и открыть панель

За это время подтянутся бинарники. Панель откроется по адресу http://<IP-роутера>:8080/detour/; ход установки виден в /var/log/detour-bootstrap.log. Логин и пароль задаются при первом входе.

Почему свой opkg-фид. Дистрибутивный фид GL.iNet застрял на sing-box 1.8.10, который не понимает схему конфига 1.13.x, а tpws из zapret не пакует вообще никто. Поэтому проект держит собственный подписанный фид на обе архитектуры и обновляет его автоматически, сверяясь с релизами upstream.
Требования к железу. Роутер на OpenWrt с musl либо Keenetic с установленным Entware. Нужен root по SSH и немного места; для стабильной работы желательна флешка со SWAP — его тоже можно создать из интерфейса.
